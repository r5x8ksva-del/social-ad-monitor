# 社媒软广监测（B站 × 健康食品）

> A local web app that watches Bilibili for **undisclosed commercial promotions** ("soft ads") of health foods and supplements, and turns them into evidence-backed leads for human review. Chinese UI. Guest-only public data. Built as a research prototype for market-regulation use.

本地网页工具：自动在 B站 上发现**没有标明「广告」的商业推广**，包括软广、口播中插、整期定制、挂链带货，产出「疑似度 + 证据链」形式的线索，交给人复核。起步品类是健康食品与膳食补充（宠物产品不算）。平台自己投放的广告（信息流、开屏、贴片、搜索广告位）不在范围内。

**它给的是线索，不是违法认定。** 每条结论都要人看过才能用。

## 它做什么

点一次「立即运行」，依次做 11 步，进度和日志在网页上实时显示：

| 步骤 | 做什么 |
|---|---|
| 1 发现新视频 | 按关键词翻 B站 公开搜索结果（按发布时间），只找上一轮以后的新视频 |
| 2 划范围 | 时间窗、时长、品类词、宠物规则 |
| 3 评论区与初筛 | 置顶评论和热评，看有没有购物链接，打推广分排队 |
| 4 采集页面和音频 | 本机无头浏览器以游客身份打开视频页，下载音频 |
| 5 本机转写 | SenseVoice 语音识别，和采集同时跑 |
| 6 大模型判定 | 有没有商业推广、推广段在哪、有没有标明广告、疑似问题（对应法条） |
| 7 第二模型交叉检验 | 另一家的模型用同样的材料独立再判一遍 |
| 8 取帧 | 只下推广段附近的画面分片 |
| 9 读画面文字 | 视觉模型抄下画面上的字，代码找「广告」「不能代替药物」等字样 |
| 10 识别地区 | 内容里写到的门店、服务城市（参考，不是发布地） |
| 11 汇总线索 | 合并两个模型的结论、标出要人注意的地方、导出表格 |

网页有四页：

- **概览**：运行面板（立即运行 / 停止）、每步进度、数字卡、每轮新线索、日志、按地区汇总。
- **线索**：列表和筛选（等级、推广形式、需要注意、发布地、参考城市）。点一行打开证据：推广段、原话核对、可以跳着播的转写、截帧和画面文字、两个模型的结论、法条、存证哈希。可以在这里**复核**（确认 / 修改 / 不是推广），也能导出 CSV。
- **运行记录**：每一轮的步骤、用时、用量、日志。
- **设置**：定时（每天或每周）、每轮上限、关键词和品类口径、要不要第二模型和画面检查、地区识别、品牌方所在地对照表。

人工环节不挡流水线：原话找不到、两个模型判得不一样、画面上读到「广告」字样、有帧没读出来、创作者声明了「内容含营销信息」模型却判无推广，都只在线索上标「需要注意」，不自动改结论，等人看。

创作者声明：B站 按网信办 2026-05 的要求在标题区显示创作者声明。其中「内容含营销信息」记为单独一档披露「声明含营销信息」，列表显示「只声明含营销信息」。它不等于标明「广告」（《互联网广告管理办法》第九条），所以仍标「未标明广告」，但原话如实写明只有这条声明。

## 合规边界（写在代码里）

- 只用**游客身份**和公开页面、公开接口：不登录，不伪造签名，不改设备指纹，不过验证码。
- 限速：每次请求间隔 1.3–2 秒；被拦就等一分钟再试一次；连续 3 次拿不到就停手，这一轮后面碰 B站 的步骤全部跳过。
- 留痕：每个请求记进工作区的 `logs/requests.jsonl`，采到的证据文件记 SHA-256。
- 评论只存文字、点赞数和「是不是 UP 主自己置顶」，不存评论者身份。
- 两个模型都判无推广、也没人复核的视频，判完删音频（转写和哈希保留，设置里可以关）。
- **视频发布地**：游客看不到（按《互联网用户账号信息管理规定》，境内 IP 属地对外也只显示到省），要平台依法提供（《互联网广告管理办法》第十六条）。网页上可以导出待查清单、再导入平台给的表格。能要到这份数据的一般是市场监管部门。

使用者要自己确认采集和使用数据的合法性：遵守平台用户协议和个人信息保护相关法律，别拿去做别的事。

## 要准备什么

| 类别 | 要什么 | 说明 |
|---|---|---|
| 系统 | Windows 10 / 11（实测） | macOS、Linux 的代码按跨平台写了，但没有实机跑过 |
| 浏览器 | Microsoft Edge（Windows 自带），或 Google Chrome | 用本机浏览器，不另下载；用 Chrome 要在配置里改 `browserChannel` |
| Node.js | 24 或更高 | 用它自带的 `node:sqlite` |
| Python | 3.10 以上（实测 3.12） | 只用来跑语音识别 |
| 转写模型 | SenseVoice-Small（int8）、Silero VAD，约 230 MB | 下载地址见「安装」 |
| ffmpeg | 任一近期版本（实测 8.1） | 转写和取帧都要 |
| 火山方舟 | 火山引擎账号（要实名认证）、API Key，开通 `config/models.json` 里的三个模型 | 按 token 计费，见「用时和花费」 |
| 电脑 | 普通笔记本即可，不需要显卡 | 实测机器：核显、16 GB 内存 |

## 安装

以下命令都在项目根目录里运行。

**1. 装 Node 依赖**（只有 playwright-core，直接驱动本机浏览器）

```bash
npm ci
```

**2. 建转写用的 Python 环境**（放在项目里的 `asr/.venv`，默认配置就会找这里）

Windows（先从 python.org 装好 Python，用自带的 `py` 启动器；直接敲 `python` 可能打开的是应用商店）：

```bash
py -3 -m venv asr\.venv
```

```bash
asr\.venv\Scripts\pip install -r requirements.txt
```

macOS / Linux：

```bash
python3 -m venv asr/.venv
```

```bash
asr/.venv/bin/pip install -r requirements.txt
```

**3. 下载转写模型**，放成这个样子：

```
asr/
└── models/
    ├── sense-voice/
    │   ├── model.int8.onnx
    │   └── tokens.txt
    └── silero_vad.onnx
```

| 文件 | 下载地址 | 大小 | SHA-256 |
|---|---|---|---|
| `model.int8.onnx` | https://huggingface.co/csukuangfj/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17/resolve/main/model.int8.onnx | 239,233,841 字节 | `c71f0ce00bec95b07744e116345e33d8cbbe08cef896382cf907bf4b51a2cd51` |
| `tokens.txt` | https://huggingface.co/csukuangfj/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17/resolve/main/tokens.txt | 315,894 字节 | `f449eb28dc567533d7fa59be34e2abca8784f771850c78a47fb731a31429a1dc` |
| `silero_vad.onnx` | https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/silero_vad.onnx | 643,854 字节 | `9e2449e1087496d8d4caba907f23e0bd3f78d91fa552479bb9c23ac09cbb1fd6` |

打不开 HuggingFace 的话：sherpa-onnx 的 GitHub 发布页有同一个模型的压缩包 [`sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17.tar.bz2`](https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17.tar.bz2)（约 1 GB），解压后取其中的 `model.int8.onnx` 和 `tokens.txt`，用上表的 SHA-256 核对。

**4. 装 ffmpeg**，让命令行里能直接运行 `ffmpeg`；或者在 `config/app.json` 里写它的完整路径（见「配置」）。

**5. 火山方舟**

1. 注册火山引擎并完成实名认证，在「火山方舟」控制台创建 API Key。
2. 在控制台开通 `config/models.json` 里列的三个模型：判定用 `label`，交叉检验用 `second`，读画面和认地区用 `vision` / `location`。
3. 把 Key 放进环境变量 `ARK_API_KEY`（设好后要重新打开终端）。

模型名带日期版本，以后会下线；到时在 `config/models.json` 里换成新的。换了模型，判得准不准要重新评估。

**6. 启动**

Windows 上双击 `启动自动监测网页.cmd`。任何系统都可以用：

```bash
npm run app
```

然后打开 http://127.0.0.1:8770/ 。启动它的那个窗口要一直开着，关掉服务就停了。「概览」页的环境检查四项（方舟密钥、转写环境、ffmpeg、浏览器）都打勾就可以跑了。

## 使用

1. **设置**：改关键词、品类词、每轮上限等，点页面底部的「保存设置」，下一轮起生效。只有「搜索关键词」必填（打开定时还要填时间）；数字项留空按默认值，品类词留空就用搜索关键词判断范围，品牌、对照表、复核人留空就是不用。
2. **概览**：点「立即运行」。可以随时「停止」，下一轮会接着做没做完的视频。
3. **线索**：看结果、复核、筛选、导出 CSV。发布地要导入平台给的表格（「导出待查发布地清单」→ 交给平台 → 「导入发布地」）。
4. 想每天自动跑：在设置里打开「定时」。只有网页服务开着、电脑不睡眠时才会到点运行，错过的时段下次打开服务时补跑一次。

第一轮会找最近 3 天发布的视频，之后每轮只处理新视频。建议第一次先把「每轮最多深度分析几条」调到 20 左右，看看实际用时和用量；没做完的会自动排到下一轮。

命令行也能跑一轮（适合放进系统计划任务）：`npm run auto`。退出码 0 表示跑完，2 表示被 B站 限制，3 表示有步骤出错。网页和命令行不会同时跑同一个工作区。

## 用时和花费（参考）

- 每条视频采集、转写、判定大约 25 秒，读画面另算。默认每轮最多深度分析 150 条，按研究期的速度大约 1.5–2 小时。
- 大模型用量主要花在读画面上（每条最多 30 帧、每帧约 1.3–1.5 千 token）。一轮 150 条粗估 500 万–1000 万 token，价格以火山方舟的价目表为准。设置里关掉第二模型或画面检查能省下不少。
- 日常用的话，每轮上限要大于每天新增的量。研究期用默认的 24 个关键词，每天大约有 70–80 条范围内的新视频。

## 配置

| 文件 | 管什么 |
|---|---|
| `config/app.json` | 本机设置：工作区位置、端口、Python、模型目录、ffmpeg、浏览器。要改就复制 `config/app.example.json` 改名后再改；没有这个文件就用模板里的默认值 |
| `config/health.json` | 品类口径的初始值：关键词、品类词、品牌、最短时长等。网页「设置」里改的存在工作区的 `settings.json` |
| `config/models.json` | 三个大模型的名字和接口地址 |
| `config/brand-places.json` | 品牌方所在地对照表的初始条目（每条有公开出处） |

环境变量（优先于配置文件）：

| 变量 | 作用 |
|---|---|
| `ARK_API_KEY` | 火山方舟密钥（必填） |
| `SAM_WORKSPACE` | 工作区目录（默认项目里的 `workspace/`） |
| `SAM_PORT` | 网页端口（默认 8770） |
| `SAM_PYTHON` | 转写用的 Python |
| `ASR_HOME` | 模型目录（默认项目里的 `asr/`） |
| `FFMPEG` | ffmpeg 可执行文件 |
| `SAM_BROWSER_CHANNEL` | `msedge` 或 `chrome` |
| `SAM_NO_SCHEDULE` | 设了就不启用定时（测试用） |

工作区里是监测数据：数据库、音频、截帧、证据、导出的表格。里面有第三方作品和个人信息，**不要提交到仓库**（`.gitignore` 已经排除）。

## 换品类、换平台

网页「设置」里改的只是「找哪些视频」。换品类还要改判定规则：

- `src/labeling.mjs`：提示词里的产品类型和判定规则
- `src/legal.mjs`：问题类型和对应法条
- `src/rules.mjs`：排除规则（比如宠物产品）
- `app/lib/judge.mjs`：代码判的警示语（如「本品不能代替药物」）
- `config/health.json`：关键词、品类词、品牌

换平台（抖音、快手、小红书……）要重写跟 B站 打交道的部分：`src/client.mjs`（搜索、评论接口），`app/steps/` 里的发现、评论、采集、取帧四步。那些平台多半要登录才能看到足够的数据，先想清楚合规问题。

## 效果参考

以下是研究期（2026 年 9 月，B站 健康食品，116 条样本）的数字，只说明方法大致可行，不代表你跑出来的效果：

- 随机样本里去掉宠物产品的 74 条，有商业推广 35 条（47%）；挂了商品链接的 19 条全是推广，写明「广告」的 0 条。
- 模型初判需要人复核：116 条里改了 27 条，多是极限用语报多了、推广形式归错。
- 第二个模型（另一家）独立判 90 条，和复核结论在「有没有推广」上一致 85 条（κ 0.89）。
- 人工抽检 30 条：对 29、说不准 1。这只是一轮，也不是盲评。

## 已知局限

- 大模型会误报漏报，结论要人复核；换模型要重新评估。
- 画面只按分片抽帧，闪现的字卡、播放器浮层可能漏掉。
- B站 改接口或加强风控，采集就会停，要人处理。
- 发布地没有平台数据就是空的。
- 只在 Windows 上实测过。
